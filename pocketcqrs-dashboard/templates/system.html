Mode barrier

The write side is paused in maintenance so schema-bearing code can be swapped without a command landing half-way through the change. Nothing else about the system stops: reads, the query side and the operational API all keep serving.

Hot reload

Re-reads the backend’s functions directory. Everything compiles and validates before any live registration is touched, so a broken file leaves the previous code serving. Durable checkpoints carry over by consumer name.

  1. Effect, HTTP and cron functions reload in any mode — they add no schema.
  2. JS projection schemas and JS deciders reload only in maintenance. Reloading them while running is not refused, it is skipped, and the report says so.
  3. Deciders are re-validated against real streams on the way in; a refusal keeps the previous code.
